## 一、知识库的使命（Mission）

构建一个**自进化、自澄清、零幻觉**的私人知识管理系统。
- 像维基百科一样有结构，像 Roam Research 一样有双向链接
- 比笔记软件多了"大模型理解层"：机器能读懂知识之间的引用关系并主动补全缺口
- 最终形态：给定任意查询，系统能自动拼出一条从你的知识出发、涵盖外部资料的完整答案链

## 二、边界约束（Boundaries）

**我们是什么（Yes）：**
- 存储结构化的 Markdown 知识网络（`.md` 文件 + 双链语法）
- 承载私有经验、方法论、项目复盘（不是通用百科）
- 支持多模态来源：PDF、图片、网页剪藏
- 由大模型全权代理写入和更新

**我们不是什么（No）：**
- ❌ 不是代码仓库（代码放 GitHub）
- ❌ 不是聊天记录（放飞书/钉钉）
- ❌ 不是邮件（放 IMAP）
- ❌ 不是通用问答库（通用问题走联网搜索，不写入 Wiki）

## 三、核心论点（Core Theses）

以下三条是本知识库的**元规则**，任何 Agent 在任何时候都不能违背：

### 论点 1：双链优先于标签

> 标签（`#tag`）只能表达"属于"，双链（`[[page]]`）能表达"为什么关联"。
> 当你要打标签还是建双链时，**永远优先建立双链**。

### 论点 2：写入即承诺

> 每写入一个 `[[link]]` 之前，必须确保目标页面存在或正在创建中。
> 禁止留下悬空引用（死链），死链在日志里标记，由 `lint_flow.py` 定期清理。

### 论点 3：先分析再写，写完即同步

> `wiki_analyst` 负责在内存中完成新旧知识的碰撞分析，不做磁盘写入；
> `wiki_writer` 负责接收分析结果并执行磁盘操作；
> 两者职责严格分离，不允许跳步。

## 四、知识边界策略（Boundary Strategy）

### 什么值得写进来？

满足以下任一条件即值得写入 Wiki：
1. 我反复遇到同一个概念（至少出现 3 次）
2. 这个概念和其他已有页面形成了跨领域关联
3. 这个概念是某篇文章/书的核心论点，我需要以后快速引用
4. 这个概念是某个项目的技术决策背景

### 什么不值得写？

- 一次性的新闻（看完就忘）
- 没有形成任何双链的孤立笔记
- 别人的原文摘录（优先链接到原文，而不是复制内容）

## 五、Agent 每次摄入的必读清单

Agent 在执行 `ingest_flow` 之前，**必须按顺序读取**：

```
1. protocols/purpose.md     ← 你在这里
2. protocols/schema.md      ← 操作规范
3. data/wiki/index.md      ← 全局导航地图
4. data/wiki/log.md        ← 最新审计日志（了解当前知识库状态）
```

不读以上文件就执行写入是违规操作，写入结果无效。
