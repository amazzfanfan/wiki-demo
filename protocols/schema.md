# ============================================================
#  schema.md — 维基操作 SOP
#  本文件定义了 LLM Wiki 的操作规范、双链语法与降级策略。
#  Agent 每次写入前必须严格遵循此规范。
# ============================================================

## 一、页面命名规范

- 所有页面使用 `kebab-case`：如 `attention-mechanism.md`
- 禁止使用中文文件名
- 禁止空格，用连字符 `-` 分隔

## 二、双链语法

维基页面之间使用双向链接，格式如下：

**正向链接**（在同一仓库内引用其他页面）：
```markdown
[[target-page-name]]   ← 显示文字 = 目标页面标题（去连字符）
```

**反向链接**（引用方自动出现在被引用方的 `## Backlinks` 节）：
```markdown
<!-- backlink:source-page-name -->
```
> 注意：`<!-- backlink:... -->` 注释在渲染时不可见，但可被解析器抓取生成反向链接索引。

## 三、页面结构模板

每个 `.md` 文件必须严格遵循以下结构：

```markdown
# 页面标题（仅首字母大写）

> **Tags:** #tag1 #tag2
> **Created:** YYYY-MM-DD
> **Updated:** YYYY-MM-DD

## Abstract

（2-3 句话，说明本页面核心知识点，读者看完应该能回答"这个概念是什么"）

## Key Concepts

- **概念A**：解释
- **概念B**：解释

## Details

（展开论述，可包含子节）

## Related

- [[another-page]] — 关联说明

## References

- [引用标题](URL) 或 书籍名
```

## 四、降级策略（Fallback Strategy）

当以下情况发生时，Agent 必须执行对应降级操作：

| 场景 | 触发条件 | 降级操作 |
|------|---------|---------|
| 页面不存在 | `[[target]]` 在磁盘上找不到对应 `.md` | 自动创建 `target.md`（使用最小模板），并在当前页面追加 `[?target?]` 标记 |
| 循环引用 | 检测到 `A→B→A` | 在 `A` 的 Related 节末尾追加 `⚠️ 循环引用警告`，通知人工审查 |
| 死链（孤立页面） | 某页面无任何 `[[]]` 引用 | 由 `lint_flow.py` 定期扫描，追加到 `log.md` 的孤立页面清单 |
| 内容超载 | `index.md` 超过 500 行 | 自动将 `index.md` 拆分为 `index-part1.md`、`index-part2.md`，并更新全局引用 |

## 五、文件禁止操作

- ❌ 禁止修改 `data/wiki/log.md` 以外的文件时间戳（由系统自动维护）
- ❌ 禁止删除任何已存在的 `.md` 文件，只能新增或局部编辑
- ❌ 禁止写入 `data/raw/` 目录（仅 `raw/` 来源层是只读的）
- ❌ 禁止在 `data/wiki/` 以外创建任何文件

## 六、写入原子性

每次写入必须是**单一页面**操作：
1. 先读取目标文件（如存在）
2. 在内存中完成修改
3. 一次性写回（`edit_tools.py` 负责 `str_replace` 精密替换）
4. 追加审计日志到 `log.md`

禁止：读取 A → 修改 B → 修改 C → 一次性写回 A/B/C（破坏原子性）。

## 七、冲突处理

当多个 Agent 并发写入同一页面时：
- 由 `ingest_flow.py` 持有文件锁（`fcntl`）
- 冲突时拒绝写入，追加 `log.md` 并报告给调用方
