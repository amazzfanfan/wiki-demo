## 三、Wiki 多Agent架构分析

### 3.1 三阶段流水线

```
用户提问
    │
    ▼
┌─────────────┐
│ 分析师Agent  │ ── 本地KB检索 + 联网外脑搜索
└──────┬──────┘
       │ 输出：标注【本地】/【外脑】的知识片段
       ▼
┌─────────────┐
│ 编辑Agent   │ ── 整合片段，去噪（排除同名无关概念），构建推理链路
└──────┬──────┘
       │ 输出：结构化知识框架 + 结论
       ▼
┌─────────────┐
│ 写手Agent   │ ── 生成类比例子，教学过程设计，格式化输出
└──────┬──────┘
       │ 输出：面向用户的完整回答
       ▼
    用户
```

### 3.2 架构差异总览

| 维度 | Wiki 知识系统 | 智编 RAG | 千问/元宝/ChatGPT |
|------|-------------|----------|-------------------|
| 核心架构 | 多Agent协作 + 结构化KB | 检索→拼接→LLM总结 | 端到端LLM生成 |
| 知识来源 | 本地KB + 联网外脑 | 论文库检索 + 网络 | 预训练参数 + 联网 |
| 来源透明 | ⭐ 【本地】/【外脑】 + 文档名 | [R]/[W] 编号 | ❌ 无来源标注 |
| 概念辨析 | ⭐ 编辑Agent主动过滤噪声 | ❌ 可能混入噪声 | ❌ 无辨析机制 |
| 知识可演进 | ⭐ 本地KB可持续扩充 | 加论文即生效 | 不可控 |
| 诚实性 | ⭐ KB无覆盖时明确标注 | ❌ 不告知检索充分性 | ❌ 可能生成幻觉 |
| 回答风格 | 深度推理 + 教学类比 + 分层 | 检索拼接 + 学术罗列 | 风格各异 |

**关键区分**: Wiki的优势是**架构性的**（难以通过简单优化获得），其他系统的优势主要是**数据性的**（可通过扩充KB弥补）。

### 3.3 Wiki四大不可替代能力

| # | 能力 | 说明 |
|---|------|------|
| 1 | **来源透明标注** | 【本地】/【外脑】+ 文档名，用户可判断可信度 |
| 2 | **概念辨析** | 主动排除同名但不同领域的概念（如Q4排除两个无关"n"） |
| 3 | **诚实标注盲区** | KB无覆盖时明确标注"本地知识库为空" |
| 4 | **多Agent深度推理** | "物理本质→工程指标→实际案例"多层拆解 |

> 关于跨题关联：Wiki架构天然支持多轮对话中的跨题知识关联，但本次评测每题均使用独立新对话，未测试此能力，不进入评分。

## 五、量化评分结果

### 5.1 评分方法

每题满分10分，六维评分：

| 维度 | 权重 | 满分 | 说明 |

### 7.3 核心判断

```
Wiki的优势 ──── 架构性的（难以通过简单优化RAG/LLM获得）
  ├── 来源透明（【本地】/【外脑】）
  ├── 概念辨析（编辑Agent主动去噪）
  ├── 诚实标注（KB盲区不编造）
  └── 知识库可演进（结构化持续积累）

Wiki的短板 ──── 数据性的（可通过扩充KB和数据模板弥补）
  ├── 板形力学论文未入库（Q3）       → P0
  ├── 工艺参数速查表不足（Q6, Q9）    → P0
  ├── 故障诊断操作模板缺失（Q9, Q10） → P1
  └── 开放分析案例不够（Q11, Q12）    → P1
```

> **Wiki当前落后于元宝和ChatGPT的领域，100%可以通过扩充KB来弥补；而Wiki在来源透明、概念辨析上的领先，其他系统难以通过简单优化获得——这是长期结构性优势。**
